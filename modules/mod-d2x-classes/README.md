# mod-d2x-classes

The AzerothCore module behind the Necromancer (class 12) and Sorceress (class 13). The generators in
`tools/d2x` write the classes' spells, talents, creatures and the rows that bind them to these scripts
(`python -m tools.d2x.build`); the module does what a DBC or database row cannot.

## Files

| File | What it holds |
| --- | --- |
| `src/D2xIds.h` | Generated by `python -m tools.d2x.build` (`moduleids.py`): every skill's talent, rank and spell IDs, the extra prerequisites, the spells taught at login and the IDs the scripts name. Never edit it by hand. |
| `src/d2x_loader.cpp` | `Addmod_d2x_classesScripts()`, which AzerothCore calls because of the folder name. |
| `src/D2xClasses.h`, `.cpp` | Shared helpers: which class a player is, minion scaling, the newest-minions limit, corpse search. |
| `src/d2x_player.cpp` | Player hooks: talent points, extra prerequisites, the spellbook, minion rescaling, spells taught at login. |
| `src/d2x_minions.cpp` | The AI of skeletons, skeletal mages and revived monsters. |
| `src/d2x_necromancer.cpp` | Raise Skeleton, Raise Skeletal Mage, Corpse Explosion, Poison Explosion, Revive, Iron Maiden, Life Tap, Blood Golem, Confuse, Attract. |
| `src/d2x_sorceress.cpp` | Static Field, Fire Wall, Thunder Storm, Energy Shield, Hydra, Frozen Orb. |
| `src/d2x_shared_spells.cpp` | Bone Armor's spell-power absorb, the line spells (Bone Spear, Lightning), Absolution. |
| `src/d2x_compatibility.cpp`, `D2xWire.h` | Recipient-specific stock class/spell/faction presentation and checked variable-length aura/party packet rewriting for ordinary clients. |

## Private integration prerequisite

The compatibility module requires the accompanying core's `PrivateClassPolicy.h`,
`WorldSession::CanUsePrivateClassAssets`, packet replacement hook and dynamic-object
field hook. Apply the private opt-in core patch in `server/core-patches` before
building this version against an older checkout. The installed isolated binary
does not load source files; updating this repository does not activate anything.

The normal realm sends stock Mage/Warlock identities and donor spell visuals to
all sessions. Only an explicitly enabled preview alias, the locally bound account,
the versioned addon marker and a real client session enable custom presentation.
The alias uses the same world and character database. Creation, enumeration,
login, storage loading, bot login and companion recruitment have independent core
checks. Keep account IDs in ignored local configuration, never in module source.

Stock fields and broadcasts are preserved: rewrites use a per-recipient copy,
consume complete variable-length records and never replace arbitrary matching
integers. Minion models use existing stock assets. Unit, dynamic-object, aura,
combat, party, identity and inspection paths all need mixed-client verification;
the focused wire tests alone do not constitute gameplay acceptance.

## How it works

- **Skills are talents.** Each of the 60 skills is one talent with five ranks, and each rank learns hidden
  "chunk" spells whose spell modifiers grow the skill (the `spellbook.py` docstring has the ID layout). The
  module keeps a skill's spellbook spell known exactly while the active spec holds a rank of it.
  `OnPlayerFreeTalentPointsChanged` fires after the talent frame, a reset, a level-up and a spec switch, so
  the spellbook and the minions follow every talent change.
- **A talent point per level from level 1.** The core starts points at level 10; the module adds
  `min(level, 9)`.
- **Up to three prerequisites.** The client and the core know one prerequisite per talent.
  `OnPlayerCanLearnTalent` refuses a talent missing any other and tells the player "Requires a point in X."
- **Minions.** Creatures 950000-950999 and revived monsters get their health, armor and damage from
  `creature_classlevelstats` in `ScaleMinion`. A golem takes its skill's effect 1 as a percent of base health
  and damage, and a revived monster twice its template health (template multipliers capped at 5). The
  masteries are dummy auras on the owner; the "minion bonus" aura carries their sum onto each minion.
  Scaling is absolute, so it reruns on every talent change and a mastery reaches minions already out.
- **Corpses.** A corpse skill takes the selected corpse, else the nearest usable one within its effect 0
  radius, and refuses with `SPELL_CUSTOM_ERROR_NO_NEARBY_CORPSES` when there is none. Using a corpse casts the Death Knight's
  "Corpse Exploded" transform (51270) on it, which marks it used. Usable means flesh and bone, not player
  owned and not a class minion; Revive also refuses rares, bosses and anyone offering a service.
- **Absolution** resets the class's talents, since no trainer serves these classes.

## Changing it

- Build with `stack\build-server.ps1`, then deploy with `stack\deploy-server.ps1`, which restarts the D2
  servers. A new source file needs `-Reconfigure`: CMake collects a module's files when it configures.
- Change IDs in the generators, never in `D2xIds.h`. A script binds to its spell through the
  `spell_script_names` row `worldsql.py` writes from a `SpellDef`'s `script` name, which must match the
  name the script registers.
- **A script that caps its own damage in `OnHit` needs `ATTR2_CANT_CRIT` on the spell.** The core adds the
  critical bonus after the `OnHit` handlers run, so a crit would double the capped amount (Static Field).
- **Helper spells that are not hidden are magic damage and can crit.** Iron Maiden's reflect and the Life Tap
  and Blood Golem heals pass an exact share of a blow, which a crit raises by half; checks of that share
  compare only non-critical hits.
- **Stock code assumes the eleven stock classes.** Grep for `getClass()`-indexed lookups before trusting a new
  core or module path with classes 12 and 13.
- Prove a change on the running stack with `python -m tools.d2x.livecheck` (the package docstring has the
  options): it plays every skill against monsters and compares what the server does with the spell data.
